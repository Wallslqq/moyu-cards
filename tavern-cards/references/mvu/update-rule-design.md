# MVU：讨论并生成变化规则

> 本篇覆盖更新规则的**设计确认**与**YAML 格式化落盘**两个半步，对应流程第 3 步。字段说明（type/range/format/check/value）与完整示例见 `references/mvu/update-rules-guide.md`——两篇配合使用：本篇管「讨论哪些规则、怎么确认」，guide 管「字段怎么写」。

## 一、输入与职责

从项目读取 `schema.ts`、`世界书/变量/initvar.yaml`、已有规则文件与 `创作规划.yaml` 的 `mvu` 段，不要求作者重新粘贴。

结构脚本提供字段类型、动态集合项目结构、完整枚举和约束；开局值提供实际起点。已确认的设计与本轮创意说明更新意图。首次创作缺少结构或开局文件时，说明应先完成对应步骤（`references/mvu/design-dialogue.md` / `references/mvu/initvar-design.md`）；已有文件修复不强迫重走设计流程。

本轮只回答：「游玩中依据什么事实更新现有变量，什么情况下保持不变？」不把人设、世界观再写一遍。

## 二、选择必要规则

逐个字段判断：

1. 是否允许由模型更新？`_`前缀或已确认仅由代码维护的字段不进入规则（前缀语义见 `references/mvu/guide.md`「MVU 变量特殊前缀」）。
2. 字段名和结构是否已能表达普通更新？作者没有特殊条件时，可不额外写规则。
3. 触发时机、知情边界、变化幅度或增删方式有没有真实歧义？只处理实际需要。
4. 多个字段是否遵循同一语义？可以合并，不重复堆积。

**没有专门规则不等于变量失效。不要为「完整」添加空泛check。**

## 三、逐轮确认更新行为

每轮先回答作者，再只问一个重要问题；已说明的事实不换词追问。

按当前字段需要确定：正文中什么事实触发更新、什么情况下保持、谁必须知情、怎样增减或替换、集合何时增删、哪些字段必须同步变化。范围与固定选项沿用结构；单次幅度或阶段切换只采用作者确认的规则。

`check`是给剧情模型阅读的自然语言判断，不是要编译成结构脚本的代码。只写能区分允许更新与保持不变的条件，不写「根据剧情合理更新」这样的空话，也不穷举所有未来事件。

若需要新增字段、改变类型或权限，先在变量结构（`schema.ts`）确认调整，再补对应开局值；只是起点不对则改 `initvar.yaml`。

## 四、确认设计

第一次整理用`<MVU变量规则设计终稿_待确认>`，作者确认后按下述格式整理，作为生成 YAML 的唯一依据：

```text
<MVU变量规则设计终稿>
规则对象：变量或同规则字段组
对应字段：结构中的真实路径
触发事实：允许改变所必需的事实
保持条件：仅在需要时出现
知情边界：仅在需要时出现
变化方式：替换／增减／插入／删除／移动
变化幅度：仅在作者要求时出现
集合操作：仅在集合需要专门规则时出现
复合一致性：仅在实际需要时出现
无需专门规则：已确认无需特殊限制的可更新字段
</MVU变量规则设计终稿>
```

只保留实际需要的栏目；没有特殊规则时明确「需要正式规则：无」。不夹带初始数据、代码、旧稿或被否决规则。

## 五、生成变量更新规则.yaml

文件写入 `世界书/变量/变量更新规则.yaml`，注册为 `[mvu_update]变量更新规则` 条目（条目注册由收尾 patch 完成，见 `references/mvu/guide.md` 收尾步骤 2），固定起始结构为：

```yaml
---
变量更新规则:
```

只写需要专门规则的字段；无特殊规则时保留上述空规则模板，不生成虚构条目。条目配置由打包器完成。

- 路径从真实顶层字段开始，不带`stat_data`外壳或JSON Pointer斜杠前缀。
- 同一对象的规则合理嵌套；同规则的固定字段可以合并为`${同类字段}`，不能掩盖规则差异。
- 动态映射以映射字段本身为键，不写`${未知动态键}`假路径；完整项目类型放入`type: |-`的TypeScript索引签名。
- 字符串省略`type`，数值写`type: number`，真假写`type: boolean`，固定选项用`type`填写Schema的完整字面量联合。
- 复合类型完整表达，不用object、省略号或开局空集合代替未来项目结构。
- format、range、category只在已确认要求需要时出现。

check使用精简、可执行判断的自然语言，不是JavaScript、表达式、伪代码或函数体。只采用确认的触发、保持、知情、幅度和集合增删条件，不夹带人设、初值、结构教程或JSON Patch示例。

`_`开头或仅代码维护的字段不列规则。规则路径对应Schema与开局数据的真实结构；动态对象未来项目类型由Schema提供，不要求为了检查临时塞入示例物品。要增加变量，先在变量结构确认；只是改初值则回开局值，不要让结构迁就错误的规则路径。

## 六、交付

输出一份完整yaml写入文件，核对语法、路径、权限、类型与更新语义。实际未运行时不声称通过运行测试。复杂文件可以按顶层分组使用可清理的控制注释，但不是有效YAML的必需条件。

规则文件落盘后，三份核心文件已齐，按 `references/mvu/guide.md` 收尾步骤继续（复制模板、应用 patch、校验、第 4 步 MVU 一致性检查交叉核对三文件）。检查或运行是否通过，以实际结果为准。
